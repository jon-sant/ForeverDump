# Self-hosting Forever's UI source and API data

Use this when a new WoW Forever build drops and you don't want to wait for the community repos.
It goes with [INSTRUCTIONS-console.md](INSTRUCTIONS-console.md). Scripts are in `tools/refresh/`.
Everything here was checked on 2026-10-07 against build **1.60.1.70245** (`wow_classic_beta`). Anything I couldn't test is marked **UNVERIFIED**.

**Short version:** almost everything can be regenerated **without the game client**. The UI source and the DB2 tables come straight from Blizzard's public CDN, with the same tool Gethe's CI uses. Only runtime facts (what actually exists in `_G`, CVar values, secret-value behaviour, frames and widgets, event recordings) need the game, and ForeverDump collects those.

## 1. How each community source is produced

| Source | How it's made | Needs the client? | Evidence |
|---|---|---|---|
| **Gethe/wow-ui-source** `forever` branch | A GitHub Actions job (`.github/workflows/export.yml`, started by hand with `workflow_dispatch`) calls the composite action on the `automation` branch with `product: wow_classic_beta`. That action builds **TACTTool** (submodule `wowdev/TACTSharp`, pinned to `de24db8`, .NET 9), reads BuildConfig and CDNConfig from `https://us.version.battle.net/v2/products/<product>/versions`, extracts 3 manifest files (FileDataIDs 6067012 `ui-code-list.txt`, 6067013 `ui-toc-list.txt`, 6076661 `ui-gen-addon-list.txt`), then extracts every file they list, then commits and tags the result. | **No.** It's pure CDN extraction. | [forever branch](https://github.com/Gethe/wow-ui-source/tree/forever), [export.yml](https://github.com/Gethe/wow-ui-source/blob/forever/.github/workflows/export.yml), [automation/action.yml](https://github.com/Gethe/wow-ui-source/blob/automation/action.yml), [ExportInterfaceFiles.ps1](https://github.com/Gethe/wow-ui-source/blob/automation/ExportInterfaceFiles.ps1), [TACTSharp](https://github.com/wowdev/TACTSharp) |
| **Ketho/BlizzardInterfaceResources** `forever` branch | The README says the data is "Dumped from the KethoDoc addon": GlobalAPI, WidgetAPI, Events, CVars, LuaEnum, Frames and FrameXML are dumped **in game**. GlobalStrings and AtlasInfo are downloaded from wago.tools (Ketho/WowDoc `projects/UpdateResources`). Templates and Mixins are parsed from the FrameXML source (WowDoc `DumbXmlParser`). Commits are manual, one per build, by Ketho. | **Yes** for the runtime dumps; no for strings, atlases and templates. | [BIR forever](https://github.com/Ketho/BlizzardInterfaceResources/tree/forever), [KethoDoc](https://github.com/Ketho/KethoDoc) (maps `WOW_PROJECT_CAMELOT`), [WowDoc](https://github.com/Ketho/WowDoc) (default `TACT_PRODUCT = "wow_classic_beta"`, `camelot = "camelot" -- forever`) |
| **Ketho/vscode-wow-api** | LuaLS annotations generated by Lua scripts (`luasrc/annotate`, using WowDoc) from Blizzard's own `Blizzard_APIDocumentationGenerated` tables, plus wiki-parsed data and hand-written widget, FrameXML and library files. Released per Mainline version (README badge 12.0.1). | No (built from the extracted source plus the wiki). It ships **Mainline** data, not a Forever flavor. | [repo](https://github.com/Ketho/vscode-wow-api), `luasrc/annotate/init.lua`, `Annotations/Core/*` |
| **wago.tools** | Marlamin's successor to wow.tools. It watches Blizzard's patch service, downloads every build from the CDN, and serves the builds list, files and DB2-as-CSV (the same stack as [wow.tools.local](https://github.com/marlamin/wow.tools.local): TACTSharp + DBCD + WoWDBDefs). | **No.** CDN only. | [wago.tools](https://wago.tools), [builds API](https://wago.tools/api/builds), [warcraft.wiki.gg: WoW.tools](https://warcraft.wiki.gg/wiki/WoW.tools) |

## 2. Our approach compared, artifact by artifact

| Artifact | Community source | Can we reproduce it ourselves? | Without it we lose |
|---|---|---|---|
| Blizzard UI Lua/XML/TOC, including `Blizzard_APIDocumentationGenerated` | Gethe | **Yes, client-free:** `tools/refresh/extract_ui_cdn.sh`. **Tested:** 4,422 files, byte-identical to Gethe's `forever` branch after EOL normalisation. The in-game `ExportInterfaceFiles code` produces the same content but needs the client. | Nothing |
| API docs (functions, events, secret flags) | Gethe (inside the UI source) | Yes (same as above) | Nothing |
| LuaLS annotations | vscode-wow-api | Yes: generate them from our `Blizzard_APIDocumentationGenerated` (the parent converter does this). vscode-wow-api only ships Mainline. | The hand-written widget and FrameXML annotations. Use vscode-wow-api's `Annotations/Core/Widget` and `FrameXML` as a base and override them with Forever data |
| DB2 tables (spells, items, maps, atlases, GlobalStrings) | wago.tools CSV | **Yes, client-free:** `tools/refresh/extract_db2_cdn.sh` (TACTTool + DBC2CSV + WoWDBDefs). **Tested:** row sets identical to wago CSV on GlobalStrings, SpellName, Spell, SpellMisc, ItemSparse and UiTextureAtlasMember. | Hotfixes. CDN DB2s don't contain them; the client's `Cache\ADB\<locale>\DBCache.bin` does, and DBC2CSV can apply it. New tables need a WoWDBDefs update, which usually lands within hours (it already lists 70245). |
| GlobalStrings (all locales), AtlasInfo | BIR (from wago) | Yes: `GlobalStrings` and `UiTextureAtlas*` DB2s from the CDN or wago. Other locales: run TACTTool with `--locale` (**UNVERIFIED**, not tested). | Nothing |
| Templates, Mixins | BIR (parsed) | Yes: parse the extracted FrameXML, or read BIR | Nothing important |
| GlobalAPI / WidgetAPI / Events / CVars / LuaEnum / Frames, as they **really exist at runtime** | BIR (KethoDoc, in game) | **Only in game:** ForeverDump `/fdump all`. Docs can be wrong or incomplete (undocumented globals, `Environment = "SecureOnly"`, functions removed at runtime). | Ground truth on what an addon can call. **BIR already lags one build** (it's at 70205; the current build is 70245). |
| Secret-value behaviour, taint, protected calls, event payloads | none | **Only in game:** ForeverDump `probe` / `record` | First-try correctness for combat code |
| UI art (BLP textures) | none (in-game `ExportInterfaceFiles art`) | Client-free in principle: TACTTool can extract any file by FDID or name, and the community listfile has the paths. **UNVERIFIED:** no art script written. | Only matters for texture work |

**Verdict:** For first-try addon code, the combination is sufficient: client-free CDN extraction (UI source, API docs, DB2) plus ForeverDump (runtime truth). The remaining gaps are hotfixes (small; use wago CSV or `DBCache.bin`), a Forever-specific widget/FrameXML annotation layer (generate it from ForeverDump's WidgetAPI dump), and runtime behaviour that only a human session can show (combat, secret values). The community repos are still worth fetching as a cross-check (`check_build.py` shows who is behind).

## 3. Getting the community UI source and API dump

```bash
tools/refresh/fetch_community.sh [destdir=./community] [product=wow_classic_beta]
```

- `git clone --depth 1 -b forever` (or a fetch on later runs) of Gethe/wow-ui-source and Ketho/BlizzardInterfaceResources.
- Downloads `https://wago.tools/db2/<Table>/csv?branch=wow_classic_beta` for a table list. Override it with `TABLES="SpellName Map ..."`, or pin a build with `WAGO_BUILD=1.60.1.70245`.
- Tested: 27 s first run (1.6 s on refresh). Sizes: wow-ui-source 48 MB, BIR 25 MB, 20 wago CSVs about 17 MB. **Total 89 MB.**

## 4. Refreshing it yourself (no community repos)

Requirements (Linux, WSL or Git Bash): `git`, `curl`, `python3`, `ping` (TACTSharp pings CDNs to rank them; without it you get "Exhausted all CDNs"), and the .NET 9 SDK (`curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 9.0`). On native Windows you can also run Gethe's own `ExportInterfaceFiles.ps1` with pwsh, after building TACTTool.

| Step | Command | Needs client? | Tested result |
|---|---|---|---|
| Detect build | `tools/refresh/check_build.py` | No | Prints patch service, wago.tools, Gethe and BIR versions. Exit code 10 = new build since last run |
| UI source | `tools/refresh/extract_ui_cdn.sh wow_classic_beta out/ui` | No | 4,422 files, 49 MB, about 11 s (after a first-run CDN cache of about 650 MB) |
| DB2 → CSV | `tools/refresh/extract_db2_cdn.sh wow_classic_beta out/db2` (`TABLES=...`, or `ALL=1`) | No | 18 tables in 8 s (39 MB). `ALL=1` (1,161 tables listed for 70245 in WoWDBDefs): 20 s, 140 MB. 608 CSVs; 552 tables are empty in Forever; 1 converter failure (`SpellMissileMotion`) |
| Everything | `tools/refresh/refresh_all.sh [--force]` | No | 40 s with a warm cache. Writes `foreverdump/data/{ui-source,db2,community}` and commits the UI source to a local git repo (one commit per build, so `git diff HEAD~1 --stat` shows what Blizzard changed) |
| Runtime truth | In game: `/fdump all`, then copy `WTF\Account\<ACCOUNT>\SavedVariables\ForeverDump.lua` | **Yes** | See INSTRUCTIONS-console.md §3 |
| UI from your install (optional) | In-game `ExportInterfaceFiles code` at the glue screen (INSTRUCTIONS-console.md §2) | Yes | Same content as the CDN path |
| DB2 from your install (optional) | TACTTool has `--basedir <WoW install>` to read local files instead of the CDN | Needs the installed files, not a running client | **UNVERIFIED** for `_classic_beta_` |

Disk: the TACTSharp CDN cache in `tools/refresh/.cache/work-wow_classic_beta` is **about 840 MB**. Delete it any time; it re-downloads only what's needed. Nothing multi-GB is downloaded.

### Build detection and automation
- Authoritative: `https://us.version.battle.net/v2/products/wow_classic_beta/versions`. Columns: `Region|BuildConfig|CDNConfig|KeyRing|BuildId|VersionsName|ProductConfig`. The CN Forever product is `wow_cn_beta` (region `cn`).
- Mirrors: `https://wago.tools/api/builds/wow_classic_beta/latest` (JSON: version, created_at, build_config). Gethe `version.txt` on `forever`. BIR README `GetBuildInfo()` line.
- Cron example (hourly): `0 * * * * /path/foreverdump/tools/refresh/refresh_all.sh >> /path/refresh.log 2>&1`. Running it while the build hasn't changed is a 1-second no-op.

## 5. Combat log and chat log

### What addons can and can't do on Forever (build 70245)
- **`COMBAT_LOG_EVENT_UNFILTERED` (CLEU) is not usable by addons.** Forever's own API doc (`CombatLogDocumentation.lua`) marks `COMBAT_LOG_EVENT` and `COMBAT_LOG_EVENT_UNFILTERED` `HasRestrictions = true`. warcraft.wiki.gg says CLEU is "no longer accessible to addons in Midnight since Patch 12.0.0" and that registering it "Fires ADDON_ACTION_FORBIDDEN". Forever's UI turns that event into the popup "*<addon> has been blocked from an action only available to the Blizzard UI*" with **Disable/Ignore** buttons (`EventImplementation.lua`, `GameDialogDefs.lua`). `pcall` does not suppress that popup.
- **`CombatLogGetCurrentEventInfo` is gone.** It's not in Forever's API docs and not in Ketho's runtime GlobalAPI dump (70205). The payload getters exist only as `C_CombatLogSecure.GetCurrentEventInfo` (`Environment = "SecureOnly"`) and `C_CombatLogInternal.GetCurrentEventInfo` (fed by `COMBAT_LOG_EVENT_INTERNAL_UNFILTERED`). Neither appears in the runtime GlobalAPI dump, so addons can't reach them.
- **What remains for addons in `C_CombatLog`:** filter, retention and message-limit settings, plus `C_CombatLog.IsCombatLogRestricted()`.
- **Alternatives that exist on Forever:**
  - `UNIT_COMBAT` (forever-addon-kit measured plain amounts);
  - `C_DamageMeter.*` (`SecretWhenInCombat = true`, so read it **after** combat; events `DAMAGE_METER_*`);
  - `UNIT_SPELLCAST_*`, `PLAYER_SWING` and `C_SwingTimer.*`;
  - `COMBAT_TEXT_UPDATE` with `C_CombatText.GetCurrentEventInfo`;
  - `ENCOUNTER_START`/`ENCOUNTER_END` and `PLAYER_REGEN_*`.
  - Health values are secret in combat (forever-addon-kit, wowforeverguides).
- **The client's text combat log still exists.** `/combatlog` → `LoggingCombat()` (Forever `SlashCommands.lua`). Addons can call `LoggingCombat(true|false)` and `C_ChatInfo.IsLoggingCombat()` → `enabled, advanced` (both in the runtime dump). **UNVERIFIED:** whether `LoggingCombat` is protected on Forever, and whether the file content is limited the way the addon feed is. On retail Midnight the file is still written for external log sites.

### Collecting a combat log (human steps)
1. Optional, for extra unit data: turn on the **Advanced Combat Logging** checkbox in the **Network** settings category. On retail that category sits under Options → System; **UNVERIFIED** whether Forever nests it the same way. Forever's settings define this checkbox for CVar `advancedCombatLogging` (default `0`, "Whether we want advanced combat log data sent from the server"). The console alternative is `/console advancedCombatLogging 1`.
2. Type `/combatlog`. Chat shows Forever's string `COMBATLOGENABLED`: "Combat being logged to Logs/WoWCombatLog".
3. Play the fight, then type `/combatlog` again to stop (or log out).
4. Find the file in `_classic_beta_\Logs\`. CVar `combatLogUniqueFilename` defaults to `1` ("Write combat log file with a timestamped name per client launch"), so expect `WoWCombatLog-<timestamp>.txt`. **UNVERIFIED:** the exact timestamp pattern; pick the newest `WoWCombatLog*.txt`.
5. Format, per warcraft.wiki.gg: the first line is `COMBAT_LOG_VERSION,<v>,ADVANCED_LOG_ENABLED,<0|1>,BUILD_VERSION,<ver>,PROJECT_ID,<id>`. Each line after that is `<date time>  SUBEVENT,` then base params, prefix params, 17 advanced params (when advanced logging is on) and suffix params. **UNVERIFIED** for Forever: the version number, the timestamp layout (it has changed across retail versions), and `PROJECT_ID`. Parsers should read the header line instead of assuming.
6. Privacy: the file contains other players' names and GUIDs. Send only logs you're asked for, and zip them (they're large).

### Collecting a chat log
- `/chatlog` toggles `LoggingChat()`. Chat shows `CHATLOGENABLED`: "Chat being logged to Logs/WoWChatLog.txt". The file is `_classic_beta_\Logs\WoWChatLog.txt`. **UNVERIFIED:** the line format on Forever.
- It contains private conversations and names. **Don't send it** unless you're debugging chat code, and then edit it first.
