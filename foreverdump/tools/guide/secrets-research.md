## TL;DR

1. **None of the 7 "documented-secret-but-clear" APIs contradict the docs.** Six of them returned nothing, because they are Nilable, MayReturnNothing, or only meaningful during an event or cast. v2.1 counted those nils as "clear". The seventh, `UnitCastingDuration`, returns a **duration object**. `issecretvalue(obj)` is always false for such an object; you have to ask `obj:HasSecretValues()`. [USER-SV + DOCS]
2. **The `C_Spell.GetSpellCooldown` finding is documented.** The function carries `SecretWhenCooldownsRestricted = true`. In the `SpellCooldownInfo` struct, `startTime`, `duration`, `modRate`, `activeCategory` and `timeUntilEndOfStartRecovery` lack `NeverSecret`, while `isEnabled`, `isActive` and `isOnGCD` have `NeverSecret = true`. The SV matches this exactly: in combat the five unflagged fields are secret and the three flagged ones are clear; out of combat all are clear. The verifier did not push the function-level predicate down to struct fields. [DOCS S4 + USER-SV]
3. **The restriction "flipping" in The Barrens is the normal Combat restriction.** It is not anomalous. `ADDON_RESTRICTION_STATE_CHANGED(0, 1)` (Combat, Activating) fires at combat start and `(0, 0)` (Inactive) fires together with `PLAYER_REGEN_ENABLED`. The docs say the event fires *before* activation and *after* deactivation, so **no event with state 2 (Active) is ever delivered**. The in-combat snapshot polled `GetAddOnRestrictionState(0) == 2`. [DOCS S4 + USER-SV]
4. **`SecretReturns` means unconditional on Forever.** `UnitHealth`, `UnitHealthPercent`, `UnitPower` and `UnitGetTotalAbsorbs` are secret out of combat in the open world, including for `"player"`. This contradicts community claims that "out of combat all data is readable" (S10) and is consistent with the wiki (S1). [USER-SV vs COMMUNITY]
5. **The community docs about `WOW_PROJECT_ID` are outdated.** S7, S8 and S9 say `WOW_PROJECT_ID == 1` (Mainline) on builds 69913/70009. On 70245 it is **18 = `WOW_PROJECT_CAMELOT`** (`WOW_PROJECT_MAINLINE` is still 1). S9 also notes the game type "Camelot" may be renamed. Don't hard-code either value. [USER-SV vs COMMUNITY]
6. Forever = the Mainline 12.1.5 secret system. The full `C_Secrets`, `C_RestrictedActions`, `addon*RestrictionsForced` CVars, `taintLogObjectSecrets`, AuraContainer, curves and duration objects are all present. [OFFICIAL S6 + DOCS S4/S5]

## 1. Mechanics of secret values

### 1.1 Sourced facts
- **What a secret is** [DOCS S1]. A secret is an opaque wrapper returned to *tainted* (addon) code. Untainted (secure Blizzard) code can operate on it normally. Tainted code **may**:
  - store it in variables and tables (as a value),
  - pass it to Lua or C functions,
  - concatenate it (`..`) and use `string.format`, `string.concat` or `string.join`. The result is a secret string.
  - call `type(x)`, which returns the real underlying type.
  - display it through "sinks" such as `FontString:SetText`, `StatusBar:SetValue`, `Cooldown:SetCooldownFromDurationObject` and curves.
- **What errors immediately in tainted code** [DOCS S1]: arithmetic, ordered comparison, `#`, using the secret as a table key, indexing it, calling it, and boolean-testing a secret *boolean*. A non-boolean secret can be truth-tested.
- **Comparison relaxations** [OFFICIAL S2, Blizzard WoWUIDev post 2025-11-04, Alpha 6]:
  - `==` between possibly-secret values of different types gives a non-secret `false`.
  - `nil == nil` gives a non-secret `true`.
  - `if x then` is treated as `type(x) ~= "nil"`.
  - `tonumber()` on a secret string is no longer allowed.
  - **Contradiction:** S1's blanket "secrets cannot be compared" is softened by this post. Equality where the types differ, and nil tests, are fine.
- **Tables** [DOCS S1]:
  - A table can be flagged "always yields secret" (every read returns a secret) or "forbidden" (indexing it raises `attempted to index a forbidden table`).
  - When untainted code stores a secret *key* in a table, the table gets both flags.
  - Since Alpha 4 (2025-10-17), structured return tables are no longer wholly secret, only their individual values [OFFICIAL S2]. That is exactly why `GetSpellCooldown`'s table is clear while its fields are secret.
- **SavedVariables** [OFFICIAL S2, Beta 1 2025-11-11]: an SV cannot contain secrets. A secret is replaced with `nil` and a comment is written in the file.
- **Debug output** [OFFICIAL S2]:
  - `/dump` prints secret contents (Alpha 4).
  - Event Trace shows the secret state of payloads (Beta 4, 2025-12-10). Blizzard_EventTrace uses `issecretvalue(arg)` behind its "Show Secret Values" setting. [DOCS S4]
- **12.0.7** [OFFICIAL S3]: `debugstack()` and `debuglocals()` **return secrets** if any function on the stack accessed a secret.
- **12.1.5** [OFFICIAL S3]: fixed a crash in `tostring()` and `dumpobject` on secret objects.
- **Global primitives present on Forever** [DOCS S5 + USER-SV `primitives`]:
  - `issecretvalue`, `issecrettable`, `hasanysecretvalues`, `canaccessvalue`, `canaccessallvalues`, `canaccesssecrets`, `canaccesstable`, `scrubsecretvalues`, `scrub`, `mapvalues`, `dropsecretaccess`, `secretwrap`, `issecure`, `issecurevariable`, `securecallfunction`, `forceinsecure`, `CreateSecureDelegate`.
  - `secretunwrap` is **nil** in the user's client (removed from globals in Beta 3 per S2, even though S4 still documents it).
- **`secretwrap`**:
  - [DOCS S4] It has no `HasRestrictions` tag.
  - [OFFICIAL] Blizzard's 2026-03-21 example uses `format("%.1s", secretwrap("Jar Jar Binks"))`.
  - [COMMUNITY S10] says it "may not work from addon code". Contradiction, unresolved. Test it in-game (§6).
- **Secret aspects on frames** [DOCS S1/S4]:
  - When a secret is fed to a widget, the widget gains a secret aspect. Examples: Text 0x8, Shown 0x20, Alpha 0x80, BarValue 0x4000, Cooldown 0x8000.
  - Later getters on that widget return secrets, and secret anchoring propagates.
  - Aspects are cleared only by `SetToDefaults()`.
  - Test with `region:HasSecretAspect(aspect)`, `region:HasSecretValues()` and `region:IsAnchoringSecret()`.
  - 12.1.0 PTR3 (2026-06-30) added **Forbidden Aspects**, AuraContainer and AuraButton [OFFICIAL S3].
- **Display helpers** [DOCS S1/S4]:
  - `C_CurveUtil.CreateCurve` and `CreateColorCurve` map a secret to a secret colour or alpha.
  - `C_DurationUtil.CreateDuration` and duration objects (`LuaDurationObject`) work with `StatusBar:SetTimerDuration` and `Cooldown:SetCooldownFromDurationObject`.
  - Since 12.0.1 (2026-03-21), `SetCooldownFromDurationObject` is the **only** way to put secret timing on a Cooldown frame [OFFICIAL S3].

### 1.2 Predicates: the tagging vocabulary [DOCS S4 `SecretPredicatesDocumentation.lua`, 70245]
- **Function and event tags that cause conditional secrecy:**
  - `SecretInActivePvPMatch`, `SecretInChatMessagingLockdown`, `SecretOnRestrictedMaps`, `SecretWhenAnchoringSecret`
  - `SecretWhenAurasRestricted`, `SecretWhenUnitAuraRestricted`, `SecretWhenCooldownsRestricted`, `SecretWhenInCombat`
  - `SecretWhenLossOfControlInfoRestricted`, `SecretWhenTotemSlotSecret`, `SecretWhenUnitSpellCastRestricted`, `SecretWhenUnitComparisonRestricted`
  - `SecretWhenUnitHealthMaxRestricted`, `SecretWhenUnitIdentityRestricted`, `SecretWhenUnitNameIdentityRestricted`, `SecretWhenUnitPossessionRestricted`
  - `SecretWhenUnitPowerMaxRestricted`, `SecretWhenUnitPowerRestricted`, `SecretWhenUnitStatsRestricted`, `SecretWhenUnitThreatStateRestricted`, `SecretWhenUnitThreatValuesRestricted`
  - `SecretWhenLuaTableHasSecretKeys` (in `LuaValuePredicatesDocumentation`, which is Forever-only and not in live)
  - `SecretWhenCurveSecret`, `SecretWhenEncounterEvent`, `SecretWhenNumericFormatterSecret`
- **Unconditional tags:**
  - `SecretReturns` on functions. "Unconditionally secret" per S1.
  - `SecretPayloads` on events.
  - `SecretValue` on fields.
- **Field-level tags:** `NeverSecret = true` (965 fields), `ConditionalSecret = true` (20).
- **Precondition tags** (calls can error or return nothing). Examples: `RequiresComparableUnitTokens`, `RequiresDeclassifiedUnitIdentity`, `RequiresFontStringTextAccess`, `RequiresNonSecretAura`, `RequiresUnitAuraAccess` (FailureMode = Error), `RequiresUnitIdentityAccess`, `RequiresValidActionSlot`.
- **`SecretArguments`** = `AllowedWhenUntainted` | `AllowedWhenTainted` | `NotAllowed`. This controls whether you may *pass* a secret *into* the API.
- **Tag counts in the Forever docs:** `SecretInChatMessagingLockdown` 100, `SecretWhenUnitStatsRestricted` 58, `SecretAccessor` 46, `SecretWhenUnitIdentityRestricted` 35, `SecretReturns` 19, `HasRestrictions` 283. 212 functions carry a `SecretWhen*`/`SecretIn*`/`SecretOn*` tag, and 34 of those return structs or tables.
- **The 19 `SecretReturns` functions on 70245:**
  - `UnitHealth`, `UnitHealthPercent`, `UnitHealthMissing`, `UnitPercentHealthFromGUID`
  - `UnitGetTotalAbsorbs`, `UnitGetTotalHealAbsorbs`, `UnitGetIncomingHeals`
  - `UnitInRange`, `UnitCastingDuration`, `UnitPowerBarTimerInfo`, `UnitSpellTargetName`, `UnitSpellTargetClass`
  - `PlayerIsSpellTarget`, `ClosestUnitPosition`, `ClosestGameObjectPosition`
  - `GetRaidTargetIndex`, `GetArenaOpponentSpec`
  - `C_CombatText.GetCurrentEventInfo`, `C_SpellDiminish.ShouldTrackSpellDiminishCategory`
  - Note: `UnitPower` is **not** tagged `SecretReturns`; it uses `SecretWhenUnitPowerRestricted` (see §3.3).
- **Events with `SecretPayloads`:** `MINIMAP_PING`, `UNIT_SPELL_DIMINISH_CATEGORY_STATE_UPDATED`, `RUNE_POWER_UPDATE`, `RUNE_TYPE_UPDATE`, `UNIT_DISTANCE_CHECK_UPDATE`, `UNIT_IN_RANGE_UPDATE`, `UNIT_MAX_HEALTH_MODIFIERS_CHANGED`.
- **Events with conditional payloads:**
  - `UNIT_AURA` (SecretWhenAurasRestricted)
  - all `UNIT_SPELLCAST_*` (SecretWhenUnitSpellCastRestricted). `castBarID` is NeverSecret. `UNIT_SPELLCAST_SENT.target` is ConditionalSecret.
  - `UNIT_DIED`, `PARTY_KILL`, `PLAYER_SOFT_INTERACT_CHANGED` (SecretWhenUnitIdentityRestricted)
  - `ARENA_CROWD_CONTROL_SPELL_UPDATE`, `UNIT_POWER_POINT_CHARGE`, `ENCOUNTER_TIMELINE_EVENT_ADDED`
  - about 100 `CHAT_MSG_*` events (SecretInChatMessagingLockdown)
  - `UNIT_AURA_BLOCKED.auraInstanceID` is `SecretValue`.
- **CLEU** [DOCS S4]: `COMBAT_LOG_EVENT` and `COMBAT_LOG_EVENT_UNFILTERED` are `HasRestrictions = true`, `CallbackEvent = true`. `C_CombatLog`, `C_CombatLogSecure` and `C_CombatLogInternal` exist. The user's SV shows `C_CombatLog.IsCombatLogRestricted() == true` both in and out of combat [USER-SV].

### 1.3 Inference
- Secrecy is decided **per value at return time** from the predicate state at that moment, then frozen into the value. A value fetched out of combat and stored stays clear. A value fetched in combat stays secret after combat ends. The verifier should therefore timestamp the *fetch*, not the *inspection*.
- Because Alpha 4 made structured tables non-secret containers, **any verifier that only checks `issecretvalue(ret1)` will miss all struct-returning APIs**. That covers 34 conditional functions, including the spell, action and spellbook cooldown and charge functions, loss-of-control, damage meter and PvP score functions.

## 2. Restriction APIs and events

### 2.1 Sourced facts [DOCS S4 `RestrictedActionsDocumentation.lua`, `SecretsDocumentation.lua`; added Beta 4 2025-12-08 per OFFICIAL S2]
- **`C_RestrictedActions`:**
  - `GetAddOnRestrictionState(type)` → `Enum.AddOnRestrictionState`.
  - `IsAddOnRestrictionActive(type)` → bool. Doc: "**will always return false during dispatch of ADDON_RESTRICTION_STATE_CHANGED**".
  - `CheckAllowProtectedFunctions(object, silent)`. TooltipDataHandler uses it.
  - `InCombatLockdown()`.
- **`Enum.AddOnRestrictionType`:** Combat 0, Encounter 1, ChallengeMode 2, PvPMatch 3, Map 4, Chat 5.
- **`Enum.AddOnRestrictionState`:** Inactive 0, Activating 1, Active 2.
- **Events:**
  - `ADDON_RESTRICTION_STATE_CHANGED(type, state)`. Doc: it fires **before** a restriction becomes active (state = Activating) and **after** it deactivates (state = Inactive).
  - `ADDON_ACTION_BLOCKED(isTainted, function)` and `ADDON_ACTION_FORBIDDEN(isTainted, function)`.
  - `MACRO_ACTION_BLOCKED` and `MACRO_ACTION_FORBIDDEN`.
- `GetRestrictedActionStatus` was added in Alpha 3 [OFFICIAL S2] and is **absent on Forever**; it has been superseded.
- **`C_Secrets`** (doc header: "How is it a secret if we can C it?"):
  - `HasSecretRestrictions()`. Doc: "If false, all APIs tagged as potentially returning secrets will never do so".
  - `GetSpellAuraSecrecy`, `GetSpellCastSecrecy`, `GetSpellCooldownSecrecy` and `GetPowerTypeSecrecy` return `Enum.SecrecyLevel` (NeverSecret 0, AlwaysSecret 1, ContextuallySecret 2).
  - `CanCompareUnitTokens`.
  - About 24 `Should*BeSecret` predicates: `ShouldAurasBeSecret`, `ShouldCooldownsBeSecret`, `ShouldUnitStatsBeSecret`, `ShouldUnitPowerBeSecret(unit, powerType)`, `ShouldUnitPowerMaxBeSecret`, `ShouldUnitHealthMaxBeSecret`, `ShouldUnitIdentityBeSecret`, `ShouldUnitComparisonBeSecret`, `ShouldUnitSpellCastBeSecret`, `ShouldUnitSpellCastingBeSecret`, `ShouldSpellCooldownBeSecret`, `ShouldSpellAuraBeSecret`, `ShouldActionCooldownBeSecret`, `ShouldSpellBookItemCooldownBeSecret`, `ShouldTotemSlotBeSecret`, `ShouldTotemSpellBeSecret`, `ShouldUnitAuraIndex/Instance/SlotBeSecret`, `ShouldUnitThreatState/ValuesBeSecret`. There is no `ShouldUnitHealthBeSecret` (see §3.3).
- **Blizzard UI uses these** [DOCS S4]:
  - CastingBarFrame → `ShouldUnitSpellCastingBeSecret`.
  - UnitFrameUtil → `ShouldUnitIdentityBeSecret` and `HasSecretRestrictions`.
  - AuraContainerUtil → `GetSpellAuraSecrecy(...) == NeverSecret`.
- **Forced-restriction CVars** [DOCS S5, 70205; history from OFFICIAL S2/S3]:
  - `addonCombatRestrictionsForced`, `addonEncounterRestrictionsForced`, `addonChallengeModeRestrictionsForced`, `addonPvPMatchRestrictionsForced`, `addonMapRestrictionsForced`, `addonChatRestrictionsForced`. Default 0, not saved.
  - Name history: Beta 3 (2025-12-01) `secretAurasForced`-style → PTR2 (2025-12-22) `secretCombatRestrictionsForced` etc. → 12.0.5 `addon*RestrictionsForced`. **Older guides use dead names.**
- **Debug CVars** [DOCS S5]:
  - `taintLog` 0–4 (1 = blocked actions, 2 = also global variables, 3 = also upvalues, 4 = also table fields).
  - `taintLogObjectSecrets` (12.1.0): logs when objects gain secret aspects or values.
  - `scriptErrors`, `luaErrorExceptions`, `enableSourceLocationLookup`, `addonLoadDebugging`, `scriptProfile`.
  - 12.0.5 (2026-04-10) fixed taint logging stopping after `/reload` and fixed tainted table reads not being logged [OFFICIAL S3].

### 2.2 User SV evidence (70245, Barrens) [USER-SV]
| Getter | Out of combat | In combat |
|---|---|---|
| `GetAddOnRestrictionState` Combat / Encounter / ChallengeMode / PvPMatch / Map / Chat | 0/0/0/0/0/0 | **2**/0/0/0/0/0 |
| `C_Secrets.HasSecretRestrictions()` | true | true |
| `C_Secrets.ShouldCooldownsBeSecret()` | false | **true** |
| `C_Secrets.ShouldAurasBeSecret()` | false | **true** |
| `C_Secrets.ShouldUnitStatsBeSecret()` | false | **true** |
| `C_CombatLog.IsCombatLogRestricted()` | **true** | true |
| `C_ChatInfo.AreOutgoingAddonChatMessagesRestricted()` | **true** (Chat restriction state 0!) | true |
| `addon*RestrictionsForced` | all "0" | all "0" |

- `ADDON_RESTRICTION_STATE_CHANGED` log: only type 0 appears. `(0,1)` arrives with `PLAYER_IN_COMBAT_CHANGED(true)` / `PLAYER_REGEN_DISABLED`; `(0,0)` arrives with `PLAYER_REGEN_ENABLED`, at the same timestamp. State 2 is never delivered as an event.

### 2.3 Inference
- The Combat restriction is tied to the player's combat flag, so in the open world it cycles with every pull. That is the "flip". Encounter, Map, ChallengeMode and PvPMatch should only change in instances, keystones, arenas/BGs and restricted maps. Chat is expected to change in encounters and PvP lockdowns.
- **Two "always-on" restrictions don't come from `AddOnRestrictionType`:**
  - `IsCombatLogRestricted() == true` out of combat in the open world. CLEU appears to be restricted at all times on Forever.
  - `AreOutgoingAddonChatMessagesRestricted() == true` while Chat state = 0.
  - Both should be tracked as separate boolean dimensions. Unverified: whether either changes inside instances or when grouped. Probe this.
- To know when "Active" begins, poll `GetAddOnRestrictionState` on the next frame after an Activating event (C_Timer.After(0)), or on `PLAYER_REGEN_DISABLED`. Never call `IsAddOnRestrictionActive` inside the event handler; it returns false by design.

## 3. The 7 "documented-secret-but-clear" APIs and the GetSpellCooldown finding

### 3.1 Per-API explanation
Each row combines the doc return type [DOCS S4] with the SV result [USER-SV]. The diagnosis is [INFERENCE] unless marked otherwise.

| API | Doc return | SV result | Diagnosis |
|---|---|---|---|
| `GetRaidTargetIndex(unit)` | `luaIndex`, **Nilable** | 0/19 secret | No raid markers were on the units, so it returned **nil**, which v2.1 counted as clear. Test: mark the target with `SetRaidTarget("target", 8)` and re-probe. |
| `UnitCastingDuration(unit)` | **`LuaDurationObject`**, MayReturnNothing | 0/18 secret | It returns a *container object*. `issecretvalue(obj)` is always false. Use `obj:HasSecretValues()` or `hasanysecretvalues`. Also: the player's own cast info is deliberately non-secret (Blizzard 2025-11-04 post, S2), and nothing is returned when not casting. |
| `UnitPowerBarTimerInfo(unit)` | MayReturnNothing | 0 secret | Only returns values while an alternate power-bar timer is running, which never happens in the Barrens. |
| `C_CombatText.GetCurrentEventInfo()` | variadic, empty `Returns` | 0 secret | Only valid inside `COMBAT_TEXT_UPDATE` dispatch. Called elsewhere it returns nothing. |
| `UnitGetIncomingHeals(unit[, healer])` | `number`, **Nilable** | the "clear" rows were combat / other units | Returns nil when no heals are incoming on that unit. Count values only when they are present. |
| `UnitSpellTargetName(unit)` | nil when not casting | self: combat 3/3 secret, ooc 3/10 secret; other units: always clear | Self is **secret whenever present**; the 7 "clear" OOC rows are nils while not casting. Other units: since 12.0.5 it "only returns names for player units" [OFFICIAL S3], so NPC casters give nil. |
| `UnitSpellTargetClass(unit)` | as above | same pattern | Same as UnitSpellTargetName. |

**Conclusion [INFERENCE]:** in 6 of the 7 cases the value was absent, and in 1 the value was a container. **No API contradicted its documentation.** The "contradiction" came from the v2.1 classifier treating nil as clear and not looking inside duration objects.

### 3.2 `C_Spell.GetSpellCooldown`
- **Docs** [DOCS S4 `SpellSharedDocumentation.lua`]:
  - The function is tagged `SecretWhenCooldownsRestricted = true` and `SecretArguments = AllowedWhenTainted`.
  - It returns a `SpellCooldownInfo` struct with `startTime:number`, `duration:number`, `isEnabled:bool [NeverSecret]`, `isActive:bool [NeverSecret]`, `modRate:number`, `activeCategory:number?`, `timeUntilEndOfStartRecovery:number?`, `isOnGCD:bool? [NeverSecret]`.
  - `C_Spell.GetSpellCharges`, `GetSpellLossOfControlCooldownInfo`, `C_ActionBar.GetActionCooldown/Charges/LossOfControlCooldownInfo` and `C_SpellBook.GetSpellBookItemCooldown/Charges/LossOfControlCooldownInfo` carry the same tag.
  - Duration-object alternatives: `C_Spell.GetSpellCooldownDuration` and `GetSpellChargeDuration`.
- **SV** [USER-SV]:
  - In combat: the five unflagged fields were 8/8 (or 6/6 for nilable ones) secret, and the three NeverSecret fields were 0 secret.
  - Out of combat: everything was clear.
  - The function-level row reads 0 secret because the *table* is not secret.
  - `ShouldCooldownsBeSecret()` flipped false→true with combat.
- **Verdict:** documented behaviour. The verifier must apply function predicate × field `NeverSecret`.
- **Whitelist** [OFFICIAL S2/S3]: certain spells are exempt and stay non-secret. These include GCD **61304**, skyriding spells and combat resurrections; 12.0.1 (2026-02-24) added healer HoTs, raid buffs, Hearthstone **8690**, Reincarnation **20608** and M+ teleports. Use `C_Secrets.GetSpellCooldownSecrecy(id)` (0/1/2) to classify a probe spell *before* interpreting results. The SV already shows `GetSpellCastSecrecy(1752) == 2` (contextual) for Sinister Strike.

### 3.3 Unconditional secrets out of combat [USER-SV vs COMMUNITY]
- **SV results:**
  - `UnitHealth`: OOC 15/15 secret, combat 7/7; context `ooc/none/self` 11/11.
  - `UnitHealthPercent`, `UnitGetTotalAbsorbs`: always secret.
  - `UnitPower`: always secret, for mana and for this character's primary power.
  - `UnitHealthMax` and `UnitPowerMax`: never secret for `player`; sometimes secret for other units. This fits `SecretWhenUnitHealthMaxRestricted`/`…PowerMaxRestricted` and the "player units are non-secret" rule.
- **Contradictions:**
  - S10 says secrets are active in all combat *and* "Out of Combat: All Data Is Readable".
  - S7 says UnitHealth, UnitHealthPercent and UnitHealthMissing are secret "in combat" for player and target.
  - Both are contradicted on 70245, where these values are secret out of combat too. S1 ("unconditionally secret" for SecretReturns) agrees with the SV.
- **UnitPower** [INFERENCE]: UnitPower is tagged `SecretWhenUnitPowerRestricted`, not `SecretReturns`, yet it reads always-secret. The likely explanation is that `C_Secrets.GetPowerTypeSecrecy(powerType)` returns AlwaysSecret for this power type on Forever. Probe it for each power type.

## 5. Porting patterns and pitfalls

### 5.1 Sourced
- **Taint message** [COMMUNITY S11]. Typical forms are `attempt to perform arithmetic on local 'textHeight' (a secret number value tainted by 'Decursive')` and `… while execution tainted by 'X'`.
  - Meaning: Blizzard (secure) code became tainted because an addon touched something it later reads, such as a global, a mixin field or a frame method. From then on, its own secret math fails.
  - The named addon is the *first* taint source recorded. It is often an embedded library, or an addon that merely wrote a field on a Blizzard frame. Decursive #51 ran for five months before it was traced.
  - ElvUI PRs #1837 and #1843 fixed similar issues by not writing to Blizzard-owned tables or frames and by using `hooksecurefunc` instead of replacing functions.
- **Safe display patterns** [DOCS S1/S4; COMMUNITY S9/S10]:
  - Feed secrets directly to widgets: `StatusBar:SetMinMaxValues(0, UnitHealthMax(u))` + `SetValue(UnitHealth(u))`; `FontString:SetFormattedText("%d", secret)`; `string.format`.
  - For percentages, use `UnitHealthPercent(u, true, curve)` with curves.
  - For timers, use duration objects and `SetTimerDuration` or `SetCooldownFromDurationObject`.
  - Never branch on, add, compare, or key a table by a secret.
- **Guard pattern:** `if issecretvalue(v) then <sink-only path> else <logic path> end`. `canaccessvalue(v)` returns true for untainted callers or non-secrets.
- **Aura APIs:** wrap in `pcall` (12.1.0 throws), or use AuraContainer and `GetSpellAuraSecrecy`.
- **SavedVariables:** never write secrets. They become nil plus a comment and you lose data silently.
- **Unknown event names** throw on `RegisterEvent`, so wrap registration in `pcall` [COMMUNITY S7; consistent with Mainline behaviour].

### 5.2 Inference
- For ForeverDump itself, run probes from a clean execution path (a fresh `C_Timer.After(0, fn)` or an event handler), not from inside hooks of Blizzard functions. Otherwise you may taint Blizzard UI and then get blamed for *its* secret errors ("tainted by 'ForeverDump'").
- Wrap every probe in `pcall`. Because of 12.0.7, don't call `debugstack()` inside an error handler that touched secrets and then store or compare the result; pass it straight to `tostring`/`print` or check `issecretvalue(stack)` first.

## 6. Detecting, logging and diagnosing secrets better (recommendations for ForeverDump v2.2)

All items in this section are [INFERENCE] built on the sourced facts above.

### 6.1 Value classifier (replaces the boolean "secret?")
Classify each return slot into one of these states:
1. `absent`: `select('#', ...)` is shorter than the doc return count.
2. `nil`: the slot is present but its value is nil.
3. `secret`: `issecretvalue(v)` is true.
4. `container-secret` or `container-clear`: `type(v)` is "table" or "userdata". For userdata, call `v.HasSecretValues` via pcall where present (duration objects, frames). For tables, use `hasanysecretvalues(v)` / `issecrettable(v)` / `canaccesstable(v)`. Then recurse into fields, one level deep for structs.
5. `clear`.

Count the denominator only for states 3, 4 and 5. Report n_present alongside n_secret.

### 6.2 Expected-secrecy model
Use the inventory TSV.
- `SecretReturns` and `SecretValue` → expect "always".
- `SecretWhen*`/`SecretIn*`/`SecretOn*` → expect "conditional". Map each tag to the matching live predicate:

| Tag | Live predicate |
|---|---|
| SecretWhenCooldownsRestricted | `C_Secrets.ShouldCooldownsBeSecret()`, or `ShouldSpellCooldownBeSecret(id)` / `ShouldActionCooldownBeSecret(slot)` / `ShouldSpellBookItemCooldownBeSecret` |
| SecretWhenAurasRestricted | `ShouldAurasBeSecret()` |
| SecretWhenUnitAuraRestricted | `ShouldUnitAura{Index,Instance,Slot}BeSecret` |
| SecretWhenUnitStatsRestricted | `ShouldUnitStatsBeSecret()` |
| SecretWhenUnitPowerRestricted | `ShouldUnitPowerBeSecret(unit, pt)` |
| SecretWhenUnitPowerMaxRestricted | `ShouldUnitPowerMaxBeSecret` |
| SecretWhenUnitHealthMaxRestricted | `ShouldUnitHealthMaxBeSecret(unit)` |
| SecretWhenUnitIdentityRestricted / NameIdentity | `ShouldUnitIdentityBeSecret(unit)` |
| SecretWhenUnitComparisonRestricted | `ShouldUnitComparisonBeSecret` / `CanCompareUnitTokens` |
| SecretWhenUnitSpellCastRestricted | `ShouldUnitSpellCastBeSecret` / `ShouldUnitSpellCastingBeSecret` |
| SecretWhenUnitThreat* | `ShouldUnitThreatState/ValuesBeSecret` |
| SecretWhenTotemSlotSecret | `ShouldTotemSlotBeSecret` |
| SecretWhenInCombat | `InCombatLockdown()` / Combat state |
| SecretInChatMessagingLockdown | Chat restriction state |
| SecretInActivePvPMatch | PvPMatch state |
| SecretOnRestrictedMaps | Map state |

- **Propagate the function tag to every struct field without `NeverSecret`.** Fields with `NeverSecret = true` must never be secret; flag them as a real contradiction if they are.
- `ConditionalSecret` fields → conditional.
- Call the matching `Should*` predicate **in the same frame, with the same arguments**, and record expected vs observed. A contradiction is only real when (predicate true and value clear and present) or (predicate false and value secret), or when a NeverSecret field is secret.

### 6.3 Restriction tracker
- On every probe batch, record a context vector:
  - `GetAddOnRestrictionState(0..5)`
  - `InCombatLockdown()`, `UnitAffectingCombat("player")`
  - `IsEncounterInProgress()`, `C_ChallengeMode.IsChallengeModeActive()`, `C_PvP.IsActiveBattlefield()`
  - `IsInInstance()` with instanceType, `C_Map.GetBestMapForUnit("player")`
  - `C_Secrets.HasSecretRestrictions()`, `ShouldAurasBeSecret()`, `ShouldCooldownsBeSecret()`, `ShouldUnitStatsBeSecret()`
  - `C_CombatLog.IsCombatLogRestricted()`, `C_ChatInfo.AreOutgoingAddonChatMessagesRestricted()`
  - the six `addon*RestrictionsForced` CVars, plus `taintLog` and `taintLogObjectSecrets`
- **Event handling:**
  - Log `ADDON_RESTRICTION_STATE_CHANGED(type, state)` with GetTime() and the *polled* state. Schedule a `C_Timer.After(0)` re-poll to capture the transition to Active, and log the latency.
  - Never use `IsAddOnRestrictionActive` inside the handler.
  - Also log `PLAYER_REGEN_DISABLED/ENABLED`, `PLAYER_IN_COMBAT_CHANGED`, `ENCOUNTER_START/END`, `CHALLENGE_MODE_START/COMPLETED`, `PVP_MATCH_ACTIVE/COMPLETE`, `ZONE_CHANGED_NEW_AREA`, `PLAYER_ENTERING_WORLD`, `ADDON_ACTION_BLOCKED/FORBIDDEN`, `MACRO_ACTION_BLOCKED/FORBIDDEN`, `UNIT_AURA_BLOCKED`.
- Treat "Activating then Inactive" with no Active event as normal; the Active state is reached between those two events.

### 6.4 Controls and self-tests (run at login and per capture)
- **Positive control:** `local ok, s = pcall(secretwrap, 1)`, then check `ok and issecretvalue(s)`. This settles the S10-vs-Blizzard contradiction. Also test `pcall(secretwrap, "x")`.
- **Always-secret control:** `issecretvalue(UnitHealth("player"))` should be true on 70245 even out of combat.
- **Negative controls:** `issecretvalue(1)` is false, and `issecretvalue(UnitHealthMax("player"))` is false.
- **Container control:** `local d = C_Spell.GetSpellCooldownDuration(61304)` → `d:HasSecretValues()`. 61304 is whitelisted, so expect false. Compare with a non-whitelisted spell in combat, which should be true.
- **Whitelist control:** `C_Secrets.GetSpellCooldownSecrecy(61304)` and `(8690)` should be 0. A class rotational spell should be 2.
- **Forced sweep:** for each type T in Combat/Encounter/ChallengeMode/PvPMatch/Map/Chat, out of combat:
  1. `SetCVar("addon"..T.."RestrictionsForced", 1)`
  2. wait one frame
  3. re-run the probe suite
  4. reset the CVar to 0
  
  This isolates which restriction drives which predicate without needing a raid or arena. The CVars are not saved, but reset them explicitly anyway.

### 6.5 Diagnostics hygiene
- Offer a `/fdump debug` toggle that sets `taintLog` to 1 or 2 and `taintLogObjectSecrets` to 1. Output goes to `Logs/taint.log`; ask the user to attach it.
- Keep your own error counter and stop probing well before the roughly 100-error cap, so real errors still surface. Prefer pcall and recording over letting errors throw.
- Never store raw probe values in SV. Store `{state = "secret"/"clear"/"nil"/"absent", type = type(v)}` only.
- As a leak check, post-process the SV file for Blizzard's "secret value replaced" comment. If it appears, a secret got into SV.
- Record `debugstack` only after checking `issecretvalue`.
- Cross-check with `/eventtrace` and its Show Secret Values option for the events in §1.2.
- Wrap `RegisterEvent` for Forever-only or uncertain events (e.g. `PLAYER_IN_COMBAT_CHANGED`, `UNIT_AURA_BLOCKED`) in pcall.
- Probe realistic states: mark a raid target, cast while targeting a player (needed for UnitSpellTargetName), have a healer heal you (UnitGetIncomingHeals), and go into a dungeon (Map/Encounter restrictions, identity secrecy for NPCs per 12.0.5).
